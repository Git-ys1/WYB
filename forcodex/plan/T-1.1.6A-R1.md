# T-1.1.6A-R1 菜单树恢复计划（仅浏览，占位，不启测量）

## 摘要
本轮从 `exp/boot-spine-r1` 出发，只恢复“完整菜单浏览树”，不恢复任何真实测量运行。  
核心原则不变：**显示单写者**（`app -> presenter -> app_display_service -> oled_smoke`）、不改 OLED 底层参数、不改 ADC/TIM/算法。  
上电仍先显示诊断页，但门槛从 10s 改为 3s，且可按 `OK` 立即进入菜单。

## 三、菜单模型重构（决策完成）

## 页面枚举（固定）
在 `app_menu_tree.h` 定义：
- `UI_DIAG`
- `UI_MAIN_MENU`
- `UI_DEBUG_MENU`
- `UI_DEBUG_ADC`
- `UI_BOOT_INFO`
- `UI_MEASURE_MENU`
- `UI_RES_RANGE`
- `UI_RES_READY`
- `UI_VDC_READY`
- `UI_FREQ_READY`
- `UI_CONT_READY`
- `UI_DIODE_READY`

## 菜单数据结构（固定）
- `menu_state_t`（当前页、光标、当前功能、当前电阻档、menu_unlocked 标志）
- 光标索引按页面独立保存，返回父页时恢复上次选中项（不重置）

## 导航规则（固定）
1. `UI_DIAG`  
- 上电默认进入  
- 3s 后 `menu_unlocked=true`  
- `OK`：若已解锁，直接进 `UI_MAIN_MENU`（支持“立即跳过等待”）  
- `BACK`：留在 `UI_DIAG`  
- 其他键忽略

2. `UI_MAIN_MENU`（`DEBUG` / `MEASURE`）  
- `UP/DOWN` 切选  
- `LEFT` 选 `DEBUG`，`RIGHT` 选 `MEASURE`  
- `OK` 进入对应子菜单  
- `BACK` 回 `UI_DIAG`

3. `UI_DEBUG_MENU`（`ADC DEBUG` / `BOOT INFO`）  
- `UP/DOWN/LEFT/RIGHT` 切选  
- `OK` 进入 `UI_DEBUG_ADC` 或 `UI_BOOT_INFO`  
- `BACK` 回 `UI_MAIN_MENU`

4. `UI_DEBUG_ADC`  
- 显示 RAW/MV/VDDA/STAT  
- `BACK` 回 `UI_DEBUG_MENU`

5. `UI_BOOT_INFO`  
- 显示 STAGE/FAULT/MENU ENABLE/DISPLAY READY  
- `BACK` 回 `UI_DEBUG_MENU`

6. `UI_MEASURE_MENU`（`RES/VDC/FREQ/CONT/DIODE`）  
- `UP/DOWN/LEFT/RIGHT` 移动选项  
- `OK` 进入：
  - `RES -> UI_RES_RANGE`
  - `VDC -> UI_VDC_READY`
  - `FREQ -> UI_FREQ_READY`
  - `CONT -> UI_CONT_READY`
  - `DIODE -> UI_DIODE_READY`
- `BACK` 回 `UI_MAIN_MENU`

7. `UI_RES_RANGE`（`AUTO/200/2K/20K/200K`）  
- `UP/DOWN/LEFT/RIGHT` 切档  
- `OK` -> `UI_RES_READY`  
- `BACK` -> `UI_MEASURE_MENU`

8. READY页（`UI_RES_READY/UI_VDC_READY/UI_FREQ_READY/UI_CONT_READY/UI_DIODE_READY`）  
- 固定占位文本  
- `BACK`：
  - `UI_RES_READY` 回 `UI_RES_RANGE`
  - 其他 READY 回 `UI_MEASURE_MENU`
- `OK`：仅提示/蜂鸣，不进入 RUN
- 不触发真实测量

## 四、代码分层与单写者规则

## 新增 `app_menu_tree.*` 职责
1. 维护菜单状态与键事件迁移（状态机）
2. 提供 `app_menu_build_frame(app_ui_frame_t *frame, const app_runtime_data_t *rt)` 输出当前页文本
3. 不做显示 flush，不调用 OLED 后端

## `app.c` 调整
1. 删除散落的 if/else 导航逻辑，改为调用 `app_menu_tree_handle_key(...)`
2. 诊断等待门槛改为 `BOOT_DIAG_STABLE_MS = 3000u`
3. `app_ui_tick()` 中：
- 只做数据更新 + 构建 frame + **一次** `app_ui_presenter_flush()`
- 失败沿用现有 bootdiag fault 上报（不改机制）
4. `app_measure_tick()` 继续门控为“不运行真实测量”
5. 诊断页 ADC 采样更新保留（`UI_DIAG`、`UI_DEBUG_ADC` 页面允许）

## 显示调用红线
- 正式路径 `oled_smoke_flush_full()` 仍只能在 `app_display_service.c` 内部被调用
- 本轮不得新增第二个 flush 点

## 六、测试用例（本轮必须）

1. `R1-BOOT-DIAG`  
上电进入诊断页，稳定显示 5 分钟无黑屏/花屏。

2. `R1-DIAG-GATE`  
3 秒后可自动进菜单；3 秒内按 `OK` 可立即进菜单（跳过等待）。

3. `R1-TREE-NAV`  
完整浏览：
- 主菜单
- DEBUG 菜单
- ADC DEBUG
- BOOT INFO
- MEASURE 菜单
- RES RANGE
- 各 READY 页

4. `R1-KEYS`  
`UP/DOWN/OK/BACK` 全部行为正确；`LEFT/RIGHT` 在主菜单可横向切换模块。

5. `R1-ADC-DEBUG`  
`UI_DEBUG_ADC` 持续更新 `RAW/MV/VDDA/STAT`，不触发故障。

6. `R1-MEAS-GATE`  
浏览页与 READY 页均不启动真实测量；`RES_RUN` 不可达。

7. `R1-SINGLE-WRITER`  
全工程检查正式路径只有一个 flush 调用点（`app_display_service.c`）。

8. `R1-BOOT-SPINE-INTACT`  
断开 OLED 时仍可通过 PB12 看到故障报码（预期 3 闪），说明 boot spine 未被破坏。
