# T-1.1.7-R1 最终执行计划（4键收缩 + RES手动档 Live）

## 摘要
本轮在当前 `exp/menu-tree-r1` 稳定基线上，只做两件事：
1. 输入从 6 键收缩为 4 键（`LEFT/RIGHT/OK/BACK`）。
2. 在菜单中正式接入 `UI_RES_RUN` live 页，启用手动电阻档实时显示与计算（优先验收 `2K/20K/200K`，`200` 标记实验档）。

显示链路继续冻结为单写者：
`app -> presenter -> app_display_service -> oled_smoke`，不恢复 dirty flush / Soft-I2C / recover。

  - `OK=PC13`
  - `LEFT=PB2`
  - `RIGHT=PB10`

## 2) 菜单页类型

- 新增 `UI_RES_RUN`。
- 保留现有树结构，READY 页继续存在。

## 3) 电阻测量模块（新增）
新增 `Measurements/measure_res.h/.c`，接口固定：
```c
typedef enum {
    RES_STAT_OK = 0,
    RES_STAT_OPEN,
    RES_STAT_SHORT,
    RES_STAT_OVR,
    RES_STAT_ERR
} res_live_stat_t;

typedef struct {
    bool valid;
    uint16_t raw_u16;
    uint32_t mv;
    uint32_t vdda_mv;
    float r_ohm;
    res_live_stat_t stat;
    app_err_t err;
} res_live_sample_t;

app_err_t measure_res_manual_sample(uint8_t range_sel, res_live_sample_t *out);
const char *measure_res_range_name(uint8_t range_sel);   // AUTO/200/2K/20K/200K
bool measure_res_range_is_exp(uint8_t range_sel);        // 200 档 true
```

`range_sel` 与菜单 `RES_RANGE` 选择一一对应：
- `AUTO=0`（不运行）
- `200=1`（实验档）
- `2K=2`
- `20K=3`
- `200K=4`

## 四、实现步骤（按顺序）

## A. 4键输入收缩
1. `bsp_keys` 删除 UP/DOWN 枚举与扫描。
2. 初始化仅配置 PC13、PB2、PB10、PB11 输入上拉。
3. 去除代码中所有 `KEY_UP/KEY_DOWN` 分支，改成 LEFT/RIGHT 对应减一/加一。

## B. 菜单导航统一为4键
在 `app_menu_tree.c` 统一规则：
- `LEFT`：上一项/减一
- `RIGHT`：下一项/加一
- `OK`：进入/确认
- `BACK`：返回
- 主菜单仍保留 LEFT->DEBUG，RIGHT->MEASURE 的直达语义（满足“横向切模块”）。

## C. 新增 `UI_RES_RUN` 路径
菜单流固定：
`MEASURE -> RES -> UI_RES_RANGE -> OK -> UI_RES_READY -> OK -> UI_RES_RUN`

返回规则：
- `BACK` 于 `UI_RES_RUN` 返回 `UI_RES_RANGE`
- `UI_RES_READY` 中 `BACK` 也返回 `UI_RES_RANGE`

## D. RES 手动 live 计算接入
在 `measure_res.c` 实现：
1. 采样来源：
- `adc1_read_filtered(&raw, &mv)`（Vred_mV）
- `adc1_read_vdda_mv(&vdda_mv)`（失败回退 `3300`）
2. 量程参考电阻（固定常量）：
- `200 -> 100Ω`
- `2K -> 1kΩ`
- `20K -> 10kΩ`
- `200K -> 100kΩ`
3. 公式（按 `RES.png`）：
`Rx = Rref * Vred / (Vdda - Vred)`
4. 状态判定（先简化）：
- `mv <= SHORT_TH` -> `SHORT`
- `vdda_mv - mv <= OVR_TH` -> `OVR`
- `mv >= vdda_mv - OPEN_TH` -> `OPEN`
- 其余 `OK`
- ADC/HAL 错误 -> `ERR`
5. AUTO 档策略：
- 不进入真实计算，返回 `ERR_NOT_IMPL`（页面显示 `RUN DISABLED`/`STAT:ERR`）

## E. app 层门控与节奏
`app.c`：
1. 保持 `MEAS_PERIOD_MS = 40ms`。
2. 新增 `RES_RUN_UI_REFRESH_MS = 100ms`（仅 `UI_RES_RUN` 页面生效）。
3. `app_measure_tick()`：
- 仅当 `app_menu_is_run_page()==true` 才调用 `measure_res_manual_sample()`
- 非 `UI_RES_RUN` 立即返回，不采样
4. `app_ui_tick()`：
- 仍保持单一 flush 调用点（presenter）
- `UI_RES_RUN` 页面下按 100ms 刷新，其余保持 200ms

## F. UI 文案落地（RES_RUN）
`UI_RES_RUN` 页面 5 行固定：
1. `RES RUN <RANGE>`（200 档显示 `RES RUN 200 EXP`）
2. `R: ...`（自动 Ω/KΩ 显示）
3. `MV: <vred_mv>`
4. `RAW:<raw>`
5. `STAT: OK/OPEN/SHORT/OVR/ERR`

`UI_RES_READY` 保持：
- `RES READY`
- `RANGE: ...`
- `PRESS OK TO RUN`
- `RUN DISABLED`（仅提示，不自动启动其它测量）

## 六、风险与回退

## 主要风险
- 菜单页与测量页刷新职责混写，导致再次争屏。
- 非运行页误触发测量采样，造成 UI 节奏紊乱。

## 硬回退条件
出现任一即停止并回退：
- 黑屏/花屏
- `UI_RES_RUN` 进入即 fault
- 非 `UI_RES_RUN` 页面仍在采样
- 出现第二个 flush 调用点
- 为提速引入 dirty flush

## 回退命令
- 已提交问题：`git revert HEAD && git push`
- 未提交问题：`git restore .`
