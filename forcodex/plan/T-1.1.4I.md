# T-1.1.4I 黑屏修复最终计划（基于当前 H 代码现状收敛版）

## 摘要
本轮唯一目标不变：**上电 1 秒内 OLED 必有固定 BOOT 文本**；若仍黑屏，**bootdiag 必须能唯一定位卡点**。  
已完成现状核查：`T-1.1.4H` 的大部分框架已在仓库中（bootdiag、TIM2延后、救屏模式、HW/SW双路径、恢复链路）但仍黑屏，主因收敛为：

1. OLED 总线“自动回退策略”粒度过粗：当前在底层 `bsp_i2c_write/probe` 任意一次失败就即时切 Soft-I2C，容易形成总线模式抖动。  
2. 恢复与刷新仍可能互相抢占：尽管已有阈值控制，但恢复触发点仍分散，导致“偶发闪烁+黑屏”。  
3. 启动可见性不足：当前虽然有 BOOT banner 路径，但没有严格单状态机控制“谁能改总线、谁能触发恢复”。

本轮改法：**不推翻 H，做“策略收口”**，把总线切换与恢复都收归 `app.c` 的单一状态机。

---

## 范围与约束（严格执行）
1. 不改 `.ioc`，不重生代码。  
2. 不改 SWD（PA13/PA14）。  
3. 不改测量公式、量程逻辑、菜单定义。  
4. 不引入阻塞式 `HAL_Delay` 闪灯/死等。  
5. 只改以下文件：

## 关键接口与行为冻结（对外）
## 1) 保留并继续使用
- `bootdiag_get_stage() / bootdiag_get_err() / bootdiag_get_ms()`
- `bsp_oled_bus_set_mode() / bsp_oled_bus_get_mode() / bsp_oled_bus_reset_stats() / bsp_oled_bus_get_nack_count()`
- `bsp_i2c2_bus_recover() / bsp_i2c2_reinit_100k()`

## 2) 行为语义调整（本轮重点）
- `bsp_i2c_write/probe` 对 OLED 总线：**不再“底层自动切换 HW/SW”**。  
  底层仅返回成功/失败并累计计数；总线切换权仅属于 `app` 的 OLED 状态机。
- Soft-I2C 仍保留，但只在状态机显式下发时启用。

## 实施步骤（顺序固定）

## Step 0：稳态守护（不动既有正确项）
1. 维持 `TIM2_IRQn=3`、`TIM6_IRQn=1`。  
2. TIM2 IC 继续只在 `BOOT_40` 后启动。  
3. `APP_OLED_RESCUE_MODE=1` 保持开启。  

DoD：构建通过，下载连接稳定。

---

## Step 1：把 OLED 启动流程改成“单一主状态机”
在 `app.c` 新增内部状态机（仅内部类型，不对外）：
- `OLED_BOOT_IDLE`
- `OLED_BOOT_HW_PROBE`
- `OLED_BOOT_HW_INIT`
- `OLED_BOOT_HW_FLUSH`
- `OLED_BOOT_SW_PROBE`
- `OLED_BOOT_SW_INIT`
- `OLED_BOOT_SW_FLUSH`
- `OLED_BOOT_DONE`
- `OLED_BOOT_FAIL_WAIT`

规则：
1. 上电进入 `HW_PROBE`：只探测 `0x3C/0x3D`（trials=5, timeout=20ms）。  
2. HW 路径任一步失败后进入 SW 路径（盲初始化仍按 `0x3C -> 0x3D`）。  
3. 任一路 `FLUSH` 成功即写 `BOOT_40`，显示两行固定文本。  
4. 失败写 `BOOT_EXx`，不阻塞主循环，进入 `FAIL_WAIT` 等待重试节拍。  

DoD：stage 变化单调且可复现，不出现跨阶段回跳。

---

## Step 2：恢复链路收口（唯一入口）
所有 OLED 恢复动作只允许在 `app_oled_recover_tick()` 里触发，其他路径禁掉 recover 调用。  
恢复固定序列：
1. `bsp_i2c2_bus_recover()`
2. `bsp_i2c2_reinit_100k()`
3. 切 `HW` 重试启动状态机
4. HW 失败再切 `SW` 重试
5. 成功后 `oled_invalidate_all() + full flush`

调度节拍：
- 前 10 秒：200ms
- 10 秒后：1s
- 连续失败 >= 5：置 `FAULT`，停止高频重试

DoD：任一时刻仅有一个恢复任务在跑（无并发恢复）。

---

## Step 3：刷新路径继续降级（彻底消马赛克）
1. `APP_OLED_RESCUE_MODE=1` 下 UI 刷新强制只走 `oled_flush(full)`，不走 `dirty` 主路径。  
2. BOOT 成功后前 2 秒仅保留 BOOT 固定页，不刷新复杂页面。  
3. 2 秒后再进入 DEBUG/MEAS 常规刷新。  

DoD：连续 2 分钟切页不出现静止马赛克。

---

## Step 4：RGB 降级为辅助（不阻塞主目标）
1. 保留心跳状态机与非阻塞自检（蓝→红→绿）。  
2. 若 RGB 无反应，不阻塞 OLED 验收；DEBUG 固定显示 `RGB:UNK`。  
3. `hb_kick` 停止约 1 秒进入 FAULT 行为保持。

DoD：RGB 异常不会拖累 OLED 启动链路。

---

## Step 5：bootdiag 与 DEBUG 页最终固定
DEBUG 固定输出（救屏模式下优先显示）：
- `BOOT STAGE: xx`
- `OLED ERR: Ex`
- `OLED BUS: HW/SW`
- `OLED NACK: n`
- `RGB:UNK`（若灯无响应）

并确保 Live Watch 在黑屏时仍能读到：
- `bootdiag_get_stage()`
- `bootdiag_get_err()`
- `bootdiag_get_ms()`

DoD：黑屏情况下能明确判断卡在 Probe / Init / Flush / Recover 哪一步。

## 测试用例（必须逐项）
1. `T114I-BUILD-01`：`clean + build` 0 error，生成 `WYB.hex`。  
2. `T114I-BOOT-01`：上电 1 秒内出现 BOOT 两行文本。  
3. `T114I-I2C-HW-02`：正常连线优先 HW I2C2，稳定显示 5 分钟。  
4. `T114I-I2C-FALLBACK-03`：人为使 HW probe 失败后，SW 路径仍可点亮。  
5. `T114I-BLACK-LOCATE-04`：断开 OLED 时，`bootdiag` 明确停在 EX 阶段。  
6. `T114I-MOSAIC-05`：连续切页 2 分钟，无静止马赛克。  
7. `T114I-RGB-06`：有灯则三态正确；无灯则 `RGB:UNK` 且不影响 OLED 诊断。  
8. `T114I-HB-07`：停止 `hb_kick` 后约 1 秒进入 FAULT。

## 显式假设与默认
1. OLED 仍为 SSD1306，地址仅 `0x3C/0x3D`，接线 `PC4/PA8`，上拉 3.3V。  
2. 本轮默认 `APP_OLED_RESCUE_MODE=1`，先保证“可见和可定位”，不追求 UI 完整度。  
3. Soft-I2C 只服务 OLED 写操作，不扩展到 ADS/其他设备。  
4. 本轮不推进 T-1.1.5（ADC/OPAMP/COMP 新功能）任何代码。
