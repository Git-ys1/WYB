# T-0.1.12 OLED 调试可视化落地计划（基于 `WYB`，沿用现有 SSD1306 驱动）

## 1. 摘要
目标是在不改冻结硬件映射的前提下，把当前工程升级为“上电即可看见运行状态”的调试固件，完成 M0~M3：  
1. `BOOT OK + tick` 心跳。  
2. I2C2 全地址扫描并显示 OLED 地址。  
3. SSD1306 稳定多行刷新。  
4. OLED 调试 UI 展示系统状态、模块状态、自检结果、滚动日志。  

已锁定实现偏好：  
- OLED 库方案：**沿用现有 `Drivers/drv_oled_ssd1306.*`**（不切第三方库）。  
- 页面策略：**默认进入调试页**，保留按键切换到测量页的入口。  

---

## 2. 现状与差距（基于当前工程勘察）
- 已具备：`I2C2/I2C3/TIM2/TIM16` 初始化、现有 OLED 驱动、基础自检页、主 superloop。
- 已具备：`bsp_i2c_probe()` 内部使用 `HAL_I2C_IsDeviceReady()`。
- 差距：无独立日志环形缓冲；无“模块位图状态”统一管理；无长期调试 UI 页面；无 I2C2 全扫结果可视化；无 `docs/debug_ui.md`。

---

## 3. 实施范围与边界
- 只改调试可视化相关代码，不改测量算法公式。
- 保持主循环调用顺序不变：  
`app_poll_button() -> app_measure_tick() -> app_ui_tick() -> app_beep_tick()`
- 不触发 CubeMX 重新生成。
- 不迁移目录结构。

---

## 4. 详细实施步骤（决策完备）

## A. 新增日志模块（Ring Buffer）
改动文件：  
- 新增 `App/app_log.h`  
- 新增 `App/app_log.c`

实现内容：  
1. 定义日志级别：`LOG_LVL_I/W/E`。  
2. 定义日志条目：`timestamp_ms + level + message[24]`。  
3. 环形队列容量固定 `N=32`。  
4. 提供 API：  
- `app_log_init(void)`  
- `app_log_push(log_level_t lvl, const char *fmt, ...)`  
- `app_log_snapshot(app_log_entry_t *out, uint8_t max_entries)`  
5. 提供宏：`LOGI/LOGW/LOGE`。  
6. 规则：消息存储截断到 24 字符；OLED 显示时再按单行宽度二次裁剪。

## B. 模块状态位与自检状态机
改动文件：  
- 修改 `App/app.c`  
- 可选新增 `App/app_debug.h`（仅声明内部结构时使用）

实现内容：  
1. 增加模块位图：  
- `MOD_I2C2, MOD_OLED, MOD_I2C3, MOD_ADS, MOD_TIM2IC, MOD_KEY, MOD_BEEP, MOD_MUX`  
2. 每个模块维护三态：`UNKNOWN/OK/FAIL` + `last_err`。  
3. 增加 I2C2 扫描函数：  
- 扫描地址 `0..127`，底层调用 `bsp_i2c_probe(BSP_I2C_BUS_OLED, addr, timeout)`。  
4. 记录扫描结果：  
- `found_count`  
- `found_addrs[]`（最多保存前 8 个）  
- `first_oled_addr`（优先 0x3C，否则 0x3D，否则首命中）  
5. 启动自检流程：  
- I2C2 扫描成功标 `MOD_I2C2=OK`。  
- OLED init 成功标 `MOD_OLED=OK`。  
- I2C3 探测 ADS 地址（默认 `0x48`）成功标 `MOD_I2C3/MOD_ADS=OK`。  
- TIM2IC 1 秒无有效捕获标 `MOD_TIM2IC=FAIL`（仅提示，不阻塞）。  
- KEY/BEEP/MUX 以初始化结果标记状态。  
6. 自检关键事件写日志：如 `SCAN:3C 48`, `OLED@3C OK`, `ADS NACK`。

## C. OLED 驱动小扩展（不替换库）
改动文件：  
- 修改 `Drivers/drv_oled_ssd1306.h`  
- 修改 `Drivers/drv_oled_ssd1306.c`

实现内容：  
1. 保留现有 API，不破坏调用方。  
2. 新增便捷接口：  
- `oled_draw_text_line(uint8_t line, const char *text)`，内部映射 `y=line*8`。  
3. `oled_flush()` 返回错误时由上层记录 `LOGE` 并更新模块状态。  

## D. 调试 UI 页面与按键行为
改动文件：  
- 修改 `App/app.c`

实现内容：  
1. 新增页面枚举：`UI_PAGE_DEBUG`、`UI_PAGE_MEAS`。  
2. 默认页：`UI_PAGE_DEBUG`。  
3. 按键策略：  
- 短按：切换 `DEBUG <-> MEAS` 页面。  
- 长按：在 `MEAS` 页保持原有模式切换；在 `DEBUG` 页仅记日志（不改模式）。  
4. 刷新周期：  
- 调试页 `200ms`。  
- 测量页保持现有节奏（100ms 可保留）。  
5. 调试页布局（8 行）：  
- `L0`：版本 + 心跳 + tick（M0）  
- `L1`：地址扫描结果摘要（M1）  
- `L2`：模块状态压缩串（OK/FAIL）  
- `L3-L7`：最近 5 条日志滚动（M3）  
6. 若 OLED 初始化失败：  
- 系统继续运行，不死机。  
- 日志继续在 RAM 记录。  
- `MOD_OLED=FAIL`。  

## E. 错误上报策略
改动文件：  
- 修改 `App/app.c`（必要时微调 `Drivers/drv_ads1110.c` 返回路径注释）

实现内容：  
1. 对所有关键返回值做错误折叠：  
- `ERR_I2C_NACK/ERR_ADC_TIMEOUT/ERR_NO_SIGNAL`  
2. 首次出现错误或状态翻转时写 `LOGE`，避免刷屏重复日志。  
3. 对恢复事件写 `LOGI`（如 `ADS RECOVERED`）。

## F. 文档交付
改动文件：  
- 新增 `docs/debug_ui.md`

文档内容固定包含：  
1. 屏幕布局与每行含义。  
2. 模块位图定义与状态值。  
3. 日志级别与错误码映射。  
4. 典型故障现象对照（OLED无响应、ADS NACK、TIM2无输入）。

## 6. 测试用例与验收场景

1. `T-DBG-M0`  
- 条件：上电正常。  
- 预期：`L0` 心跳符号变化、tick 单调增加。  

2. `T-DBG-M1`  
- 条件：OLED 接 I2C2，地址 0x3C 或 0x3D。  
- 预期：显示扫描命中地址，首地址正确。  

3. `T-DBG-M2`  
- 条件：连续运行 5 分钟。  
- 预期：多行刷新稳定，无花屏/卡死。  

4. `T-DBG-M3`  
- 条件：拔插 OLED/ADS、断开 PA0 输入。  
- 预期：日志区出现 `LOGE`，状态区 FAIL 可见，系统不中死；恢复后出现 `LOGI`。  

5. `T-DBG-BTN`  
- 条件：短按按键。  
- 预期：`DEBUG/MEAS` 页面可切换。  

6. `T-DBG-DOC`  
- 条件：对照 `docs/debug_ui.md`。  
- 预期：状态位、错误码、屏幕布局一致。  

---

## 7. 风险与回退
- 风险：日志过多导致 UI 可读性差。  
- 处理：只在状态变化时写错误日志，周期性信息降频到 1s。  

- 风险：OLED I2C 不稳定。  
- 处理：保持 100kHz，日志显示 `I2C2 FAIL`，不阻塞系统主循环。  

- 风险：调试页影响原测量演示。  
- 处理：保留短按切页，随时回测量页。
