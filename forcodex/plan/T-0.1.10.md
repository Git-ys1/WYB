# T-0.1.10 HAL/CMSIS 底座修复计划（先清根因，再看业务错误）

## 摘要
当前构建失败的两个主根因已明确：

1. `stm32g4xx_hal_i2c.h` 及对应 I2C 驱动源文件在工程内缺失。  
2. 编译宏用了 `STM32G474VETx`，但 CMSIS 设备头要求的是 `STM32G474xx`，导致 `IRQn_Type/__IO/uint32_t` 连锁报错。

本计划目标是把底座修到“HAL/CMSIS 不再报错”，让后续只剩业务层错误。

## 变更范围（决策已锁定）
1. 只改构建底座，不改业务逻辑文件（`App/BSP/Measurements` 业务算法不动）。  
2. 以 `STM32Cube_FW_G4_V1.6.2` 为唯一 HAL 来源。  
3. Debug/Release 两套配置同时修。  
4. 暂不重新 `Generate Code`（避免覆盖现有对接），先把工程编译链修通。

## 关键证据（当前状态）
1. 报错首条：`fatal error: stm32g4xx_hal_i2c.h: No such file or directory`（来自 `error1.txt`）。  
2. 当前工程 `Drivers/STM32G4xx_HAL_Driver/Inc` 中确实没有 `stm32g4xx_hal_i2c.h`。  
3. 当前编译命令含 `-DSTM32G474VETx`（见 `Debug/.../subdir.mk`），而 `stm32g4xx.h` 只识别 `STM32G474xx`。

## 实施步骤（可直接执行）
1. 备份当前工程元数据  
- 备份 [`.cproject`](F:/CodeForge/STM32CubeIDE_2.1.0/WorkSpace3/WYB/.cproject) 和 [`Debug/`](F:/CodeForge/STM32CubeIDE_2.1.0/WorkSpace3/WYB/Debug)（可选压缩）。

2. 补齐 HAL I2C 文件（从本机 FW 1.6.2 复制）  
- 来源目录：`C:\Users\yusu\STM32Cube\Repository\STM32Cube_FW_G4_V1.6.2\Drivers\STM32G4xx_HAL_Driver`  
- 复制到工程：  
  - `Inc/stm32g4xx_hal_i2c.h`  
  - `Inc/stm32g4xx_hal_i2c_ex.h`  
  - `Src/stm32g4xx_hal_i2c.c`  
  - `Src/stm32g4xx_hal_i2c_ex.c`

3. 修正预处理宏（Debug + Release）  
- 在 [`.cproject`](F:/CodeForge/STM32CubeIDE_2.1.0/WorkSpace3/WYB/.cproject) 的 C 编译器宏中确保存在：  
  - `USE_HAL_DRIVER`  
  - `STM32G474xx`  
- 当前的 `STM32G474VETx` 可保留但不作为设备识别宏；设备识别必须是 `STM32G474xx`。  
- 同步给 Assembler 宏（避免启动文件/汇编预处理不一致）。

4. 核对 include path（Debug + Release）  
- 必须包含：  
  - `../Core/Inc`  
  - `../Drivers/STM32G4xx_HAL_Driver/Inc`  
  - `../Drivers/CMSIS/Include`  
  - `../Drivers/CMSIS/Device/ST/STM32G4xx/Include`  
- 保留 `../Drivers/STM32G4xx_HAL_Driver/Inc/Legacy`。

5. 核对 HAL 模块开关  
- 在 [`Core/Inc/stm32g4xx_hal_conf.h`](F:/CodeForge/STM32CubeIDE_2.1.0/WorkSpace3/WYB/Core/Inc/stm32g4xx_hal_conf.h) 确认 `#define HAL_I2C_MODULE_ENABLED` 已开启。

6. 清理并重建  
- `Project -> Clean`（勾选 clean all）。  
- 删除 `Debug/` 后重新 `Build`（二选一即可，推荐删除 `Debug/` 更干净）。  
- 重新生成的 `Debug/.../subdir.mk` 中检查是否出现 `-DSTM32G474xx` 且不再缺 `i2c` 文件。

7. 结果判定  
- 通过标准：  
  - 不再出现 `stm32g4xx_hal_i2c.h` 缺失。  
  - 不再出现 `IRQn_Type/__IO/uint32_t` 大面积缺失。  
  - 若仍有错误，应转为业务代码级别（函数未实现、接口不匹配等）。
