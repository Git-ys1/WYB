# T-1.1.5-R2 渐进式菜单壳回接计划（单写者显示 + Smoke 后端）
## 摘要
本轮基于当前稳定 `OLED/ADC smoke` 基线，恢复菜单浏览与页面切换，但不恢复旧复杂显示链路。  
核心策略是：`main.c` 退出 smoke 直写，`app` 只通过一个统一 presenter 调用 `bsp_oled_smoke` 进行显示，确保全程单写者、单 flush 调用点。

## 现状结论（基于代码勘察）
1. 当前 `Core/Src/main.c` 仍是 `APP_SMOKE_OLED_TEST=1`，默认走 `SmokeOled_Run()`，不会进入 `app_*` superloop。
2. 当前 `App/app.c` 已有菜单壳和测量门控雏形，但仍包含旧 OLED 复杂路径（recover/soft bus/driver flush 分支）。
3. 当前 `BSP/bsp_oled_smoke.*` 已具备稳定文本/整屏 flush 能力，可作为唯一显示后端。

## 本轮改动范围（冻结）
1. `Core/Src/main.c`
2. `App/app.c`
3. `App/app.h`
4. `App/app_ui_presenter.c`（新增）
5. `App/app_ui_presenter.h`（新增）
6. `BSP/bsp_oled_smoke.c/.h`（仅必要适配，不改低层参数）
7. `docs/validation_checklist.md`
8. `README.md`

## 禁止项（冻结）
1. 不改 `OLED` 低层参数（SSD1315/HW I2C2@100k/page/16B chunk/remap/init）。
2. 不启用 Soft-I2C、不启用 recover 状态机、不启用 dirty flush。
3. 不改 ADC1/PC0 驱动行为，不改 TIM2，不改测量公式。
4. 不推进 VDC/FREQ/CONT/DIODE 功能。

## 公开接口与类型变化
1. 新增 `App/app_ui_presenter.h` 接口：
```c
typedef struct {
    char line[8][22];   // 8行, 每行最多21字符+NUL
} app_ui_frame_t;

app_err_t app_ui_presenter_init(void);      // 内部调用 oled_smoke_init(SSD1315, 0x3C)
bool app_ui_presenter_ready(void);
app_err_t app_ui_presenter_last_err(void);
app_err_t app_ui_presenter_flush(const app_ui_frame_t *frame); // 唯一flush入口
```
2. `app.c` 不再直接调用 `oled_flush/oled_flush_dirty/oled_draw_text_line`，统一改为构建 `app_ui_frame_t` 并调用 presenter。
3. `app_measure_tick()` 门控保留并收紧：未进入 RUN 页永远返回，不触发测量执行。

## 执行步骤（按顺序）
1. 先做 Git checkpoint（强制）：
```powershell
git status
git add .
git commit -m "checkpoint: before T-1.1.5-R2"
git push
```
2. 新建 `app_ui_presenter.c/.h`，把 `bsp_oled_smoke_fb_clear/draw_text_line/flush_full` 封装成唯一显示路径。
3. 在 `main.c` 将 `APP_SMOKE_OLED_TEST` 默认改为 `0`，进入 `bsp_init/app_init/superloop`，保留 smoke 分流代码以便快速回退。
4. 在 `app.c` 建立“单写者菜单渲染”：
   - 所有页面函数只填充 `app_ui_frame_t`。
   - `app_ui_tick()` 末端只调用一次 `app_ui_presenter_flush(frame)`。
   - 删除或编译屏蔽旧 `app_oled_recover_tick`、旧 soft/hw 切换恢复、旧 driver flush 分支调用路径。
5. 按 3 步恢复菜单壳（同一轮内分阶段验证）：
   - Step-1：只开 `L1_MODULE + L2_DEBUG_PAGE + L2_MEAS_FUNC` 浏览。
   - Step-2：在 `L2_MEAS_FUNC` 展示 `RES/VDC/FREQ/CONT/DIODE` 浏览列表，仍不运行。
   - Step-3：恢复 `L3_RES_RANGE + L4_RES_READY`，`OK` 仅提示 `PRESS OK TO RUN`，不启动真实测量。
6. 将固定 ADC 调试页并入 DEBUG 子页，周期更新 `RAW/MV/VDDA/STAT`，作为稳定对照页。
7. 收紧 `app_measure_tick()` 门控：
   - 条件必须是 `menu_level == MENU_L4_RES_RUN` 且 `meas_run_enabled == true` 才运行。
   - 本轮无 RUN 页，`meas_run_enabled` 全程保持 `false`。
8. 更新文档：
   - `README.md` 增加 R2 单写者规则与回退说明。
   - `docs/validation_checklist.md` 增加 `T-1.1.5-R2` 项。
9. 本轮结束提交：
```powershell
git add .
git commit -m "T-1.1.5-R2: staged menu shell reintegration on smoke backend"
git push
```

## 单写者规则（最终固定）
1. 唯一 flush 调用点：`app_ui_presenter_flush()`。
2. `main.c` smoke 绘屏路径与 `app.c` 菜单路径互斥，不能同时激活。
3. `app_measure_tick()` 不得写屏，显示只在 `app_ui_tick()` presenter 输出。

## 测试用例与场景
1. `R2-01` 上电进入菜单首页，5 分钟无花屏/黑屏。
2. `R2-02` 六键导航：`UP/DOWN/LEFT/RIGHT/OK/BACK` 行为正确。
3. `R2-03` Step-1 页面稳定：首页、DEBUG、MEASURE 可进退。
4. `R2-04` Step-2 页面稳定：功能列表可浏览，不运行。
5. `R2-05` Step-3 页面稳定：量程页与 `RES READY` 占位页显示正确。
6. `R2-06` DEBUG/ADC 子页持续更新 `RAW/MV/VDDA/STAT`。
7. `R2-07` 浏览页期间确认测量未启动：`app_measure_tick()`门控命中返回。
8. `R2-08` 验证唯一写者：全工程搜索仅 presenter 持有 OLED flush 调用。

## 回退条件（触发即停）
1. 出现花屏、黑屏、菜单切页乱屏、DEBUG/ADC 不稳定、浏览页误触发测量。
2. 回退优先：
```powershell
git revert HEAD
```
3. 若本轮未提交改坏：
```powershell

```

## 显式假设与默认
1. 默认 OLED 地址使用当前稳定基线地址（`0x3C`）。
2. `APP_SMOKE_OLED_TEST` 在 R2 默认值为 `0`，用于回接菜单壳；必要时可改回 `1` 快速恢复稳定 smoke。
3. 本轮不进入真实 RUN 页，不启动任何测量任务。
4. 本轮目标是“显示稳定 + 菜单壳可浏览”，不是功能恢复完整测量。
