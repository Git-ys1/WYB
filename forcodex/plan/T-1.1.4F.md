## T-1.1.4F 一次到位修复计划（OLED 黑屏修复 + RGB 心跳灯）

### 1. 摘要
本轮目标是两件事同时完成并可直接烧录验证：

1. 修复当前 `WYB` 工程 OLED 黑屏，恢复“上电可见文本刷新”。  
2. 新增低占用、非阻塞的 RGB 心跳灯（红常亮故障/初始化，绿按负载闪烁）。

已确认并冻结：
- RGB 映射按你确认值：`PE3/PE4/PE5`，`Active-Low`。  
  蓝=`PE3`，红=`PE4`，绿=`PE5`。  
- 现有 `.ioc` 未配置 RGB，也未配置 TIM6/TIM7；本轮采用“**手工初始化**（不重生 CubeMX）”降低回归风险。
- OLED 仍使用 `I2C2 PC4/PA8`，优先 100kHz。

---

### 2. 现状与根因收敛（基于当前仓库）
已核查当前工程：
- `APP_BOOT_SAFE_MODE=0`（全功能默认已开）；
- OLED 扫描只探测 `0x3C/0x3D`；
- OLED 失败后仅重试初始化，缺少 **I2C2 总线解锁 + 外设重置**；
- `bsp_i2c_probe()` 当前参数偏激进（应用层 timeout=2ms，ready trials=2）；
- `main.h/.ioc` 无 RGB 引脚定义。

因此本轮 OLED 修复主线定为：  
**“放宽探测 + 失败自动恢复（总线解锁→I2C2重初始化→重新探测/初始化OLED）+ 运行态健康判定”**。

### 4. 实施步骤（决策完备）

#### S1. OLED 黑屏修复（先做）
1. 在 `bsp_port_hal_template.c` 增加 I2C2 恢复能力（仅 OLED 总线）：
- `bsp_i2c2_bus_recover()`：  
  - 临时把 `PC4/PA8` 切 GPIO OD，上拉；  
  - SCL 输出 9 个脉冲；  
  - 生成一次 STOP 条件（SDA 低→SCL 高→SDA 高）；  
  - 复位为 AF4 I2C2。  
- `bsp_i2c2_reinit_100k()`：`HAL_I2C_DeInit(&hi2c2)` + timing=100k + `HAL_I2C_Init(...)` + filters。

2. 放宽探测参数（app 层）：
- OLED 地址探测保持 `0x3C/0x3D`，但改为：
  - `HAL_I2C_IsDeviceReady` trials = 5
  - timeout = 20ms
- 若探测都失败，仍执行“盲初始化尝试”：
  - 先 `0x3C` 再 `0x3D` 直接 `oled_init()`。

3. 加入统一恢复流程 `app_oled_recover()`：
- 触发条件：`oled_init` 失败或 `oled_flush_dirty` 连续失败 >= 3。
- 恢复动作：  
  `bsp_i2c2_bus_recover()` -> `bsp_i2c2_reinit_100k()` -> 重新扫地址 -> `oled_init()` -> `oled_invalidate_all()` 全刷。  
- 恢复调度：前 10 秒每 200ms 尝试，之后每 1 秒尝试，避免刷爆总线。

4. UI 首屏策略固定：
- OLED 初始化成功后立即：
  - `oled_clear()`
  - 写 2 行固定文本（`BOOT OK`、版本号）
  - `oled_flush()` 全屏一次
- 再回到正常 `dirty flush` 路径。

#### S2. RGB BSP（低电平点亮）
新增 `bsp_rgb`，固定宏：
- `RGB_ACTIVE_LOW = 1`
- `RGB_R=PE4`，`RGB_G=PE5`，`RGB_B=PE3`

接口：
- `bsp_rgb_init(void)`：使能 GPIOE 时钟，配置 PE3/4/5 输出，默认全灭。
- `bsp_rgb_set(uint8_t r, uint8_t g, uint8_t b)`：0/1 控制，内部按 active-low 反相写 pin。
- `bsp_rgb_off(void)`。

#### S3. 心跳模块（TIM6 中断驱动，非阻塞）
新增 `app_heartbeat`，使用 TIM6（50ms tick）：
1. `hb_init()`：
- 初始化 TIM6 到 50ms 更新中断；
- 初始状态 `BOOT`：红常亮、绿灭；
- 启动 `HAL_TIM_Base_Start_IT()`。

2. `hb_kick()`：
- 在主循环每轮调用一次，递增 `kick_counter`。

3. `hb_set_load_hint(uint16_t load_permille)`：
- 0~1000，内部映射绿灯周期：
  - `<=200` -> 1000ms
  - `201~700` -> 400ms
  - `>700` -> 150ms

4. `hb_force_fault(uint8_t on)`：
- `on=1` 立即 `FAULT`（红亮绿灭）
- `on=0` 回到 `RUN`（前提 kick 正常）

5. ISR 逻辑（`TIM6_DAC_IRQHandler` -> `HAL_TIM_IRQHandler` -> `HAL_TIM_PeriodElapsedCallback`）：
- 每 50ms 检查 `kick_counter` 是否变化；
- 连续 20 tick（1s）未变化 -> 置 `FAULT`；
- `RUN` 状态按 `blink_period_ticks` 翻转绿灯；
- ISR 内仅计数与 GPIO 写，不做格式化/打印/延时。

#### S4. 在 App 主流程接入心跳
在 `app.c`：
1. `app_init()` 最前阶段调用 `hb_init()`，初始化期红灯常亮。  
2. `run_boot_selftest()` 成功后切 `RUN`（红灭，绿闪）。  
3. 在 `app_poll_button()` 或每轮主循环入口调用 `hb_kick()`。  
4. 负载提示：
- 仅 DEBUG 页刷新：`hb_set_load_hint(200)`
- 常规菜单：`hb_set_load_hint(400)`
- RES 运行页 + ADC 采样：`hb_set_load_hint(800)`

5. 与 OLED 健康联动：
- OLED 连续恢复失败超阈值（例如 5 次）时 `hb_force_fault(1)`；
- OLED 恢复成功后 `hb_force_fault(0)`。

#### S5. 中断文件接入
在 `stm32g4xx_it.c`：
- 增加 `TIM6_DAC_IRQHandler()`；
- 在 `HAL_TIM_PeriodElapsedCallback()` 中仅分发 `TIM6` 到心跳模块（现有 TIM2 IC 回调保持不动）。

### 6. 测试用例（必须逐项）
1. `T-OLED-BOOT-01`  
上电 1 秒内出现 `BOOT OK + 版本号`。

2. `T-OLED-RECOVER-02`  
热插拔 OLED 或短时干扰 I2C2 后，系统自动恢复显示，不死机。

3. `T-OLED-ADDR-03`  
`0x3C/0x3D` 任一地址模块均可点亮（含“探测失败后盲初始化”路径）。

4. `T-HB-BOOT-01`  
上电初始化阶段红灯常亮。

5. `T-HB-RUN-02`  
正常运行绿灯闪烁；切换页面/测量状态，绿闪频率可见变化（慢/中/快）。

6. `T-HB-FAULT-03`  
临时注释 `hb_kick()`：约 1 秒后进入 FAULT（红常亮、绿灭）。

7. `T-HB-OLED-LINK-04`  
人为制造 OLED 持续失败，触发 FAULT；恢复后退出 FAULT。

8. `T-BUILD-01`  
CubeIDE Debug 构建 `0 error`，产出 `WYB.hex`。

### 7. 风险与回退
1. 风险：PE3/4/5 与实物不匹配。  
回退：只改 `bsp_rgb.c` 引脚宏，不动上层状态机。

2. 风险：I2C2 总线恢复时序不兼容个别屏。  
回退：关闭 `bus_recover`，保留 `reinit + blind init` 路径。

3. 风险：TIM6 与其他模块潜在冲突。  
回退：切到 TIM7，接口不变。

---

### 8. 显式假设与默认
1. RGB 按你确认映射：`PE3/PE4/PE5`，低电平点亮。  
2. 维持 `I2C2=100kHz` 默认，不启 400k。  
3. 不重生 CubeMX；本轮全部手工初始化，避免覆盖现有业务逻辑。  
4. 主循环业务顺序不变，仅插入轻量 `hb_kick/load_hint` 调用。
