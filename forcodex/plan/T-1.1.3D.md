# T-1.1.3D 低延迟响应计划（目标：按下即切换）

## 摘要
当前 0.5s 级“按下后才反应”不再是按键消抖主因，主因是 UI/OLED 刷新链路阻塞（`oled_flush()` 事务过多 + 菜单周期性整页重绘）。  
本计划采用你已确认的路线：**先做局部刷新**，并预留 **I2C2 400k 加速**。  
本轮明确不改 ADS 测量逻辑（按你的要求）。

## 目标与验收标准
1. 菜单页按键按下到界面变化：`< 80ms`（100k 下目标）。
2. 启用 I2C2 400k 后按键到界面变化：`< 40ms`（目标）。
3. 不引入误触：短按、长按语义保持现状（短按按下触发，长按 600ms）。
4. ADS 未接入时，`RX:ERR 1` 行为保持不变（预期 NACK）。

## 接口与类型变更（冻结）
1. 新增 OLED 局部刷新接口：
`oled_clear_line(uint8_t line)`  
`oled_invalidate_all(void)`  
`oled_flush_dirty(const oled_t *oled)`
2. 保留现有接口兼容：
`oled_init/oled_clear/oled_draw_text_line/oled_flush` 不删除。  
`oled_flush` 作为“全量兜底”，`oled_flush_dirty` 为默认路径。
3. 新增 BSP 配置开关：
`BSP_I2C2_FAST_400K`（默认 `0`，第二阶段打开）。

## 详细实施步骤
1. 按键侧只做“结构优化”，不再盲降阈值。  
`bsp_keys.c` 改为非对称消抖：按下 `2ms`、释放 `8ms`。  
保持 `poll=1ms`、`long=600ms`。  
目的：保持“按下快、释放稳”，避免继续靠极限降消抖冒误触风险。

2. 菜单刷新改事件驱动。  
`app.c` 取消菜单页固定 `120ms` 周期重绘。  
按键事件只置 `ui_dirty=true`，仅当 `ui_dirty` 时重绘菜单。  
`L4_RES_RUN` 保留测量驱动刷新，但仅在数值/错误码变化时标记对应行 dirty。  
`DEBUG` 页继续 200ms 周期，但也改成行级 dirty 更新。

3. OLED 驱动改“脏页刷新 + 批量传输”。  
`drv_oled_ssd1306.c` 内增加 `dirty_page_mask`。  
`oled_draw_*`/`oled_clear_line` 修改像素时标记对应 page 为 dirty。  
`oled_flush_dirty` 仅发送 dirty page。  
每个 dirty page 数据发送从“16 字节分包多次”改为“单次 129 字节（0x40 + 128 数据）”。  
命令写保持稳定实现（页地址+列地址），优先可靠性。

4. 主循环优先级保持不变，但交互抢占更明确。  
继续保留 `app_poll_button -> app_measure_tick -> app_ui_tick -> app_beep_tick`。  
按键事件发生时设置：`next_ui_ms = now`，`next_meas_ms = now + 60ms`。  
目的：保证本轮/下轮先出 UI 反馈，再继续测量。

5. 第二阶段加速（你已允许）。  
在局部刷新稳定后，打开 `BSP_I2C2_FAST_400K`。  
在 `bsp_port_hal_template.c` 启动时仅对 I2C2 重配到 400k（I2C3 不动）。  
若重配失败自动回退 100k，并记录日志 `I2C2 FAST FAIL -> 100K`。  
此阶段不改 ADS 代码。

## 测试用例
1. `T-LAT-KEY-01`  
场景：L1/L2/L3 菜单页单击 UP/DOWN/LEFT/RIGHT/OK/BACK。  
标准：视觉切换稳定 `< 80ms`（100k 模式）。

2. `T-LAT-KEY-02`  
场景：长按 OK（MEAS 层）。  
标准：600ms 触发，行为与原定义一致，无重复触发。

3. `T-LAT-UI-03`  
场景：连续快速按键 20 次。  
标准：无明显积压、无“需要按住半秒才反应”。

4. `T-OLED-DIRTY-01`  
场景：仅变更单行文本。  
标准：I2C 发送量明显低于全屏 flush，UI 更流畅。

5. `T-ADS-NOHW-01`  
场景：ADS 未接。  
标准：`RX:ERR 1` 保持，系统不死机，按键/菜单流畅不受明显拖累。

6. `T-I2C2-FAST-01`（第二阶段）  
场景：开启 400k。  
标准：按键到界面变化 `< 40ms`，无随机花屏/NACK 抖动；异常自动回退 100k。

## 风险与回退
1. 风险：局部刷新实现错误导致残影。  
回退：保留 `oled_flush` 全量路径，编译开关快速切回。

2. 风险：400k 下连线边沿质量不足。  
回退：`BSP_I2C2_FAST_400K=0`，保持 100k。

3. 风险：按下消抖 2ms 在个别按键上误触。  
回退：上调到 3~4ms，不改其它架构。

## 显式假设与默认
1. 维持当前 `.ioc` 不重生成为默认路径。  
2. ADS1110 仍未接入，外部 ADC 代码不做功能性改动。  
3. 默认先完成局部刷新阶段，再启用 I2C2 400k。  
4. `RX:ERR 1` 继续作为 ADS 无响应（I2C NACK）预期信号。
