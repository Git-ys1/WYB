## T-1.1.4J 最小 GPIO LED 烟雾测试落地计划（仅改 `main.c`）

### 摘要
本轮只做“工程健康性切割验证”，不碰 OLED/RGB/测量链路。  
通过在 `Core/Src/main.c` 增加编译期开关，提供两条互斥启动路径：

1. `APP_SMOKE_LED_TEST=1`：仅运行 PB12 LED 烟雾测试。  
2. `APP_SMOKE_LED_TEST=0`：完全回到现有业务入口（`bsp_init/app_init/superloop`）。

已勘察当前工程可行性：
- 当前唯一入口是 `Core/Src/main.c`，主循环完整存在。
- `MX_GPIO_Init()` 已存在。
- `PB12` 未在 `main.h` 现有 pin 宏中占用，可用于本轮外接 LED 测试。

---

### 变更范围（严格）
只修改：
- `Core/Src/main.c`

不修改：
- `.ioc`
- `App/*`、`BSP/*`、`Drivers/*`、`Measurements/*`
- `main.h`（本轮无需新增 pin 宏，直接在 `main.c` 使用 `GPIO_PIN_12`）

---

### 实施步骤（决策完备）

#### Step 1：在 `main.c` 增加烟雾测试宏与函数声明
放在 `/* USER CODE BEGIN PD */` 区域定义：
- `#define APP_SMOKE_LED_TEST 1`

放在 `/* USER CODE BEGIN PFP */` 区域声明：
- `static void SmokeLed_Init(void);`
- `static void SmokeLed_Run(void);`

#### Step 2：实现最小烟雾测试函数
放在 `/* USER CODE BEGIN 0 */` 区域实现：

1. `SmokeLed_Init()`
- `__HAL_RCC_GPIOB_CLK_ENABLE();`
- 配置 `PB12` 为：
  - `GPIO_MODE_OUTPUT_PP`
  - `GPIO_NOPULL`
  - `GPIO_SPEED_FREQ_LOW`
- 默认 `HAL_GPIO_WritePin(GPIOB, GPIO_PIN_12, GPIO_PIN_RESET);`（灭灯）

2. `SmokeLed_Run()`
- 先 `PB12=SET`，`HAL_Delay(1000);`（上电 1 秒常亮）
- 然后无限循环：
  - `HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_12);`
  - `HAL_Delay(100);`

#### Step 3：在 `main()` 做入口分流
保持 `HAL_Init()` 与 `SystemClock_Config()` 不变。  
在“外设初始化 + app 初始化 + superloop”处改为：

- 当 `APP_SMOKE_LED_TEST == 1`：
  - 仅执行 `MX_GPIO_Init();`
  - 执行 `SmokeLed_Init();`
  - 执行 `SmokeLed_Run();`（不返回）
  - 不调用 `MX_I2C2_Init/MX_I2C3_Init/MX_TIM2_Init/MX_TIM16_Init`
  - 不调用 `bsp_init()/app_init()`
  - 不进入现有业务 superloop

- 当 `APP_SMOKE_LED_TEST == 0`：
  - 保持当前原逻辑逐行不变（包括原有外设 init、`bsp_init/app_init` 与四个 `app_*_tick`）

#### Step 4：回切说明固定
- 烟雾测试：`#define APP_SMOKE_LED_TEST 1`
- 回原工程：`#define APP_SMOKE_LED_TEST 0`

---

### 接口/类型变化
无对外 API 变化。  
仅新增 `main.c` 内部静态函数与一个编译期宏：
- `APP_SMOKE_LED_TEST`
- `SmokeLed_Init()`
- `SmokeLed_Run()`

---

### 测试用例与验收场景

1. `T114J-SMOKE-01`
- 条件：`APP_SMOKE_LED_TEST=1`，按任务书接线（PB12->1k->LED阳极，LED阴极->GND）
- 期望：上电后先常亮约 1 秒，再以约 100ms 翻转闪烁

2. `T114J-SMOKE-02`
- 连续复位 3 次
- 期望：现象一致

3. `T114J-SMOKE-03`
- 使用 CubeProgrammer 连续连接/下载
- 期望：连接稳定，下载正常

4. `T114J-SMOKE-04`（硬件排查）
- 若 LED 不亮，用万用表测 PB12
- 期望：
  - 若有 0V/3.3V 交替：判定接线/LED 极性问题
  - 若始终固定不变：再回查 `main.c` 分流逻辑是否误走业务路径

5. `T114J-ROLLBACK-05`
- 条件：改回 `APP_SMOKE_LED_TEST=0`
- 期望：完整恢复原业务入口与行为

---

### 显式假设与默认
1. 本轮只做“板级生命体征”验证，不解决 OLED/RGB 根因。  
2. `PB12` 当前未被工程占用（基于现仓库检索结果）。  
3. 允许在烟雾测试模式使用 `HAL_Delay()`，用于验证 SysTick/主循环基础时序。  
4. 本轮不生成/修改任何 CubeMX 配置文件。
