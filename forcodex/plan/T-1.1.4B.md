# T-1.1.4B 稳态修复计划：先恢复可调试，再恢复功能（针对“烧录后卡死+花屏+STLink仅复位可连”）

## 摘要
目标是先把系统从“上电即异常”拉回到“稳定可下载/可调试”，再逐步恢复 OLED+ADC 功能。  
本计划按你已确认路线执行：**先稳态修复**，重点处理 4 个高风险点：

1. SWD 保留配置缺失（`.ioc` 未见 `SYS Debug = Serial Wire` 迹象）
2. 启动失败直接 `__disable_irq(); while(1)` 导致“假死”
3. 栈仅 1KB + 大量 `snprintf(%f)` 引发 HardFault 风险
4. 启动阶段外设动作过重（I2C 扫描 + OLED刷写 + ADC校准/采样）

---

## 一、实施阶段（决策完备）

## S0：救板与连接稳定（先做，1 次）
1. 连接方式固定：`Connect Under Reset`。  
2. 先 `Mass Erase`，清除可能的异常固件状态。  
3. 首次仅烧录“稳态固件”（见 S1），不带重测功能。

完成标准：
- 不按住 RST 也能稳定连接/下载 3 次以上。

---

## S1：稳态固件（最小运行，不追求功能）
改动目标：**保证 MCU 不死锁、SWD 不丢、可稳定跑主循环**。

1. 启动路径瘦身：
- `app_init()` 里先禁用重操作：
  - 暂停 I2C 全地址扫描
  - 暂停 OLED 全页刷写
  - 暂停 ADC 校准/采样
- 只保留心跳计数和按键轮询。

2. 错误处理改“可调试”：
- `Error_Handler()` 去掉 `__disable_irq()`（保留 while，但允许 SysTick/调试介入）。
- `HardFault_Handler` 增加故障标记（RAM 变量），进入可识别死循环，不做复位风暴。

3. 主循环保持原顺序不变：
```c
app_poll_button();
app_measure_tick();
app_ui_tick();
app_beep_tick();
```
但各 tick 在稳态模式下仅执行空操作/轻操作。

完成标准：
- 烧录后 MCU 不再“立即卡死”
- STLink 可直接 Attach（不按 RST）

---

## S2：SWD 保留硬化（`.ioc` 必做）
1. 在 `WYB.ioc` 明确设置：
- `SYS Debug = Serial Wire`
- 保留 `PA13/PA14` 为调试口
- 不允许被其他 GPIO 复用

2. 重新生成代码前提：
- `ProjectManager.KeepUserCode=true`（已为 true）
- 只接受 `Core/Src|Core/Inc` 中 USER CODE 以外区域被更新

3. 生成后检查：
- `main.c` 初始化顺序仍符合项目要求
- `stm32g4xx_hal_msp.c` 中 I2C/TIM 引脚不回退错位

完成标准：
- 重新生成后仍可直接 SWD 连接
- 不出现“运行后调试口失联”

---

## S3：栈与格式化风险收敛（防 HardFault）
1. 链接脚本增栈：
- `STM32G474VETX_FLASH.ld` / `...RAM.ld`
- `_Min_Stack_Size: 0x400 -> 0x1000`（必要时到 `0x1800`）

2. UI 禁用浮点格式化：
- 将 `snprintf("%.3f", x)` 全部改为整数定点格式（例如 `x_mV` -> `d.ddd` 字符串）
- 避免 `nano-vfprintf` 浮点路径触发大栈消耗

3. 保留数据计算浮点，但不在 `snprintf` 使用 `%f`

完成标准：
- 不再出现由 UI 刷新触发的随机死机/花屏
- map 中不再依赖浮点 printf 关键路径（或显著减少）

---

## S4：逐项恢复外设（分阶段打开）
按顺序恢复，每步只开一项：

1. 恢复 OLED（仅单行心跳，限频刷新）
2. 恢复 I2C2 扫描（缩小范围到 `0x3C/0x3D`，避免 0~127 全扫）
3. 恢复 ADC1 初始化（仅 `adc1_init + 单次 raw`）
4. 恢复 RES 页面字段（`ADC raw/Vred/stat`）
5. 最后恢复完整测量页面刷新节奏

每步失败即回退上一步，不并行开多项。

## 三、对外接口/类型变更
1. 新增内部运行模式（仅内部使用）：
- `APP_BOOT_SAFE_MODE`（上电保底模式）
- 不改变现有业务 API 签名。

2. 错误处理语义补充：
- `Error_Handler` 不再全局关中断
- `HardFault` 记录 fault 标志用于 OLED/日志观察（后续恢复显示后可见）

---

## 四、测试与验收场景

## T-REC-01 调试连接恢复
- 条件：正常上电
- 期望：STLink 可直接连接，不需按住 RST

## T-REC-02 稳态固件稳定性
- 条件：连续运行 5 分钟
- 期望：无死机、无复位风暴

## T-REC-03 OLED 分步恢复
- 条件：仅恢复单行刷新
- 期望：无花屏、无全屏马赛克卡死

## T-REC-04 ADC 分步恢复
- 条件：仅恢复 `adc1_init + raw`
- 期望：无卡死，`ADC stat` 可更新

## T-REC-05 全链路恢复
- 条件：恢复 RES 手动页
- 期望：可切换、可显示，系统保持可调试

---

## 五、显式假设与默认
1. 当前硬件 PC0 已接入且电压安全（0~3.3V）。
2. 本轮优先“稳定可调试”，不是精度标定轮。
3. 允许修改 `.ioc` 并重新生成（保留 USER CODE）。
4. 如任一步复现“失联/花屏”，立即回退到上一步稳定点再继续。
