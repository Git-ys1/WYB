## T-1.1.4N-R1 最终执行计划（OLED 判别轮：地址/模式/映射一次性收敛）

### 摘要
本轮仅做 OLED 判别，不推进 T-1.1.5。目标是把问题收敛到四类结论之一：硬件模式、HAL 地址、映射方向、模块本体。  
执行策略是“单 profile + 单地址 + 单后端 + 单相位停留 + 可记录日志”，避免继续引入变量。

### 当前已知状态（基于仓库只读核查）
1. 当前已有 `R3`：250ms 延时、16B 分包、诊断结构、SSD1315 优先。
2. 当前 `main.c` 仍有 `0x3C -> 0x3D` 自动回退。
3. 当前 `docs/oled_phase_report.md` 不存在。
4. 当前仍保留文本接口 `oled_smoke_show_counter()`，但本轮不使用。

## 2. 公共接口与类型变更（冻结）
1. 在 `bsp_oled_smoke.h` 新增并全局统一地址宏：
```c
#define OLED_ADDR_7BIT 0x3Cu
#define OLED_ADDR_HAL  (OLED_ADDR_7BIT << 1)
```
2. 新增地址审计接口：
```c
uint8_t  oled_smoke_get_addr7(void);
uint16_t oled_smoke_get_addr_hal(void);
```
3. 新增 phase 日志结构与读取接口：
```c
typedef struct {
  uint8_t phase_id;
  uint8_t page;
  uint8_t chunk;
  HAL_StatusTypeDef hal_status;
  uint8_t cmd_first[2];
  uint8_t data_first8[8];
} oled_smoke_phase_log_t;

void oled_smoke_get_phase_log(oled_smoke_phase_log_t *out);
```
4. 保留已有 `oled_smoke_diag_t` 与 `oled_smoke_diag_get()`，作为失败落点主通道。
5. `oled_smoke_show_counter()` 保留但不在 `main.c` 调用。

## 3. 核心实现决策（逐项落地）
### 3.1 硬件前置检查写入文档
1. 在 `docs/oled_phase_report.md` 第一节新增“背面模式位检查记录”模板。
2. 该节只记录结果，不阻塞代码编译流程。
3. 结论栏固定包含：`SPI默认 / I2C-3C / I2C-3D / 未知`。

### 3.2 HAL 地址统一审计
1. `bsp_oled_smoke.c` 内所有 HAL I2C API 仅允许传 `OLED_ADDR_HAL`（或基于统一 `addr_hal` 缓存变量）。
2. 禁止混用 `0x3C` 和 `0x78` 直接字面量。
3. 在 `main.c` 增加可观察调试变量：
- `g_oled_addr7_dbg`
- `g_oled_addr_hal_dbg`
用于 Live Watch 和报告落地。

### 3.3 单 profile、单地址打穿
1. profile 固定为 `SSD1315`，不自动切 1306/1106。
2. 地址默认固定 `0x3C`（通过 `OLED_ADDR_7BIT`）。
3. 若硬件检查明确为 `0x3D`，仅修改该宏后重测，不做运行时自动回退。

### 3.4 相位停留机制（PB12 作为相位码）
1. 相位定义固定：
- Phase1: 全黑（PB12 先闪 1 次）
- Phase2: 全白（先闪 2 次）
- Phase3: 上半白下半黑（先闪 3 次）
- Phase4: 左半白右半黑（先闪 4 次）
- Phase5: 1像素边框（先闪 5 次）
2. 每相位显示停留 `2000ms`。
3. 循环执行 1~5，相位循环中不进入文本显示。
4. 错误时进入错误闪码覆盖模式：
- 1 闪 probe fail
- 2 闪 init fail
- 3 闪 flush fail
说明：相位闪码只在成功路径使用，错误路径切换为错误闪码。

### 3.5 图案生成（page mode）
1. P1 全黑：`fb=0x00`
2. P2 全白：`fb=0xFF`
3. P3 上半白下半黑：page `0..3=0xFF`, `4..7=0x00`
4. P4 左半白右半黑：每页 col `0..63=0xFF`, `64..127=0x00`
5. P5 1像素边框：仅四边为 1，中间全 0

### 3.6 flush 日志细化（沿用16B分包）
1. 刷新保持：
- 命令：`B0+page`, `00`, `10`
- 数据：`0x40 + 16B`, 每页8块
2. 每相位记录“第一页日志”到结构：
- `phase`
- `page=0`
- `chunk=0..7` 的首失败点（或 OK）
- `hal_status`
- 首包命令与首包数据前8字节

### 3.7 remap 小矩阵（仅 P3/P4）
1. 增加 4 组方向测试：
- A1 + C8
- A0 + C8
- A1 + C0
- A0 + C0
2. 每组只跑 P3 与 P4，各停留 2 秒。
3. 默认顺序：
- 先执行常规 Phase1/2/5一次
- 再执行 remap 矩阵 P3/P4
4. 每组记录“是否方向正确/是否偏移/是否花屏”。

### 3.8 init 双方案切换
1. 仅保留两套 init：
- Init-A：R3 reference（当前序列）
- Init-B：保守版（AE, D3, 40, 20 02, A1/C8, DA12, A6, A4, AF）
2. 使用编译宏切换：
```c
#define OLED_INIT_PROFILE_A 1   // 1=A, 0=B
```
3. 两套都固定：
- 上电后 `HAL_Delay(250)`
- `AF` 后 `HAL_Delay(100)`

---

## 4. main.c 具体改动规则（仅 smoke 分流）
1. 保留三路互斥入口。
2. OLED smoke 路径内删除自动地址回退逻辑。
3. 调用顺序固定：
- `MX_GPIO_Init()`
- `MX_I2C2_Init()`
- `HAL_Delay(250)`
- `oled_smoke_init(SSD1315, OLED_ADDR_7BIT)`
- 进入相位循环
4. 不调用 `bsp_init()/app_init()/app_*tick`。

## 6. 测试用例与场景（必须逐项）
1. `N-R1-01`：固定 `SSD1315 + 0x3C` 是否稳定进入 Phase1。
2. `N-R1-02`：PB12 相位码 1~5 与屏幕图案一一对应。
3. `N-R1-03`：P3 是否严格“上半白下半黑”。
4. `N-R1-04`：P4 是否严格“左半白右半黑”。
5. `N-R1-05`：remap 4组中是否存在正确映射组合。
6. `N-R1-06`：Init-A/Init-B 对比后是否有显著改善。
7. `N-R1-07`：失败时 `stage/page/chunk/hal_status` 是否可读并落文档。

1. `P3` 稳定正确。
2. `P4` 稳定正确。
满足即冻结 OLED 层，停止继续显示驱动调整，恢复 T-1.1.5。

## 显式假设与默认
1. 背面硬件检查由人工执行，代码仅提供记录模板。
2. 默认地址 `0x3C`，除非硬件证据明确要求 `0x3D`。
3. 默认 init 先用 A，再切 B 做 A/B 对照。
4. 本轮不新增串口日志，依赖 PB12 + 内存诊断结构 + 文档记录。
5. 本轮仍维持 HW I2C2 100k，禁止 Soft-I2C 和恢复状态机。
