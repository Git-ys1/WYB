## T-1.1.4G 执行计划 V2（审查官修正版）

### 摘要
主目标不变：恢复“上电可见反馈 + OLED 黑屏可定位”。  
本版补齐调试链路保护、可观测性闭环与决策冻结，避免执行者再做二次选择。

### 关键实现改动
1. 先做 `Step0` 调试链路硬化，再做功能改动。  
固定动作：降低 `TIM2 IRQ` 优先级到低于系统关键节拍；`TIM2 IC Start_IT` 延后到 `BOOT_40_OLED_FLUSH_OK` 之后；保留 `PA13/PA14` 不动。  

2. 冻结 `bootdiag` 方案为“内嵌 `App/app.c` 接口化”，不新增源文件。  
固定新增接口：`bootdiag_get_stage()`、`bootdiag_get_err()`、`bootdiag_get_ms()`。  
固定类型：`boot_stage_t`（10/20/30/40/EXX 枚举）；`bootdiag_t` 不单独新建结构体。  

3. OLED 最小独立链路与阶段上报。  
在 `app_init` 早期执行最小 `oled_boot_banner` 路径，只依赖 `oled_init + oled_flush`；每一步都写入 `bootdiag`（成功/失败码）；失败时不阻塞主循环。  

4. I2C2 恢复链路统一且限流。  
固定流程：`bus_recover -> reinit_100k -> probe(3C/3D, 20ms, trials=5) -> oled_init -> full_flush`；前 10 秒 `200ms`，之后 `1s`；达到阈值进入 `FAULT` 并停止高频重试。  

5. RGB 诊断策略固定为四段。  
开机自检序列保留：蓝→红→绿（TIM6 tick 非阻塞）；随后进入 BOOT/RUN/FAULT 三态；ISR 仅计数与 GPIO 写。  

6. 可复核输出双通道。  
OLED 可见时显示 `BOOT STAGE` 与 `OLED ERR`；OLED 不可见时通过 STLink Live Watch 读取 `bootdiag` 接口返回值判定卡点。  

### 测试与验收
1. `T114G-BUILD-01`：`clean + build` 0 error，产出 `WYB.hex`。  
2. `T114G-REC-00`：不按住复位连续下载 3 次，均可连接并运行。  
3. `T114G-BOOT-01`：上电 1 秒内出现固定 BOOT 两行。  
4. `T114G-BOOT-02`：断开 OLED，`bootdiag` 停在 I2C/OLED 失败段，系统不死机。  
5. `T114G-I2C-REC-03`：运行中插拔 OLED，可自动恢复到 `BOOT_40` 后正常刷新。  
6. `T114G-RGB-01`：可见蓝红绿自检，随后状态灯符合 BOOT/RUN/FAULT 定义。  
7. `T114G-HB-02`：停 `hb_kick` 约 1 秒进入 FAULT。  

### 假设与默认
1. RGB 映射继续按 `PE3/PE4/PE5 + Active-Low`。  
2. I2C2 固定 `100kHz`，不启 `400kHz`。  
3. 不重生 `.ioc`。  
4. 不改测量公式与量程业务，仅做启动链路与诊断闭环。
