# T-1.1.5G-R1 启动脊柱重构执行计划（仅做可判定启动，不推进菜单功能）

## 摘要
本轮只解决“黑屏不可判定”问题，不推进菜单功能。  
目标是把系统状态变成可观测：即使 OLED 黑屏，也能靠 `bootdiag + PB12` 判断死在 `HAL/MX/BSP/Display/UI flush` 哪一层。  
OLED 底层与 ADC 驱动保持冻结不动。

## 关键实现决策（不留二义性）
1. `main.c` 取消“显示依赖 smoke 宏”  
默认永远走：`HAL_Init -> Clock -> MX_* -> bsp_init -> app_init -> superloop`。  
保留紧急 LED smoke 宏但默认关闭，仅救援用途。
2. 启动阶段上报  
每个关键节点前调用 `bootdiag_set_stage(...)`。  
`main` 进入 while 后持续调用 `bootdiag_heartbeat_tick()`。
3. `Error_Handler()` 改造  
进入前先写：`BOOT_FAULT + 对应fault code`，然后在循环内持续 `bootdiag_heartbeat_tick()`；不允许纯无信息死循环。
4. PB12 灯语义  
Boot：快闪（100ms 翻转）  
Run：慢闪（500ms 翻转）  
Fault：报码闪烁（N次 150ms on/off + 800ms 间隔循环）
5. Display service 状态机  
状态固定：`DISP_UNINIT, DISP_INITING, DISP_READY, DISP_FAULT`。  
仅 `app_display_init_once()` 允许 init。  
`app_display_render()` 与 `app_display_render_fault()` 内禁止再触发 init。  
`show_*` 不得偷 init，不得递归 fallback。
6. 单写者规则  
唯一显示 flush 调用点固定在 `App/app_display_service.c` 内部私有函数。  
`app.c` 仅组装 frame，`app_ui_presenter_flush()` 仅转发到 display service。  
`app_measure_tick()` 禁止写屏。
7. 最小诊断页优先  
只要 `DISP_READY`，上电先显示固定诊断页：  
`BOOT OK`  
`STAGE: xx`  
`FAULT: xx`  
`RAW: xxxx`  
`MV : xxxx`  
8. 菜单本轮仅最小壳  
仅在满足 `BOOT_RUN + DISP_READY + 诊断页稳定10秒` 后允许显示：  
`MAIN MENU`  
`> DEBUG`  
`MEASURE`  
不做多级跳转恢复，不进入 RUN 页。
9. 测量门控继续收紧  
`app_measure_tick()` 仅当 `MENU_L4_RES_RUN && meas_run_enabled` 才执行。  
本轮 `MENU_L4_RES_RUN` 不可达。

## 文件级实施步骤
1. 新增 `app_bootdiag.c/.h`，实现阶段/故障变量与 PB12 非阻塞灯状态机。
2. 修改 `main.c`  
接入 bootdiag 阶段上报。  
去掉显示路径对 smoke 宏依赖。  
改造 `Error_Handler()` 写 fault 信息并进入可观测循环。
3. 修改 `app_display_service.c/.h`  
重构为显式状态机。  
删除 show 内隐式 init 与递归 fallback。  
保留固定 OLED 后端调用（仍用 `oled_smoke_*`）。
4. 修改 `app_ui_presenter.c/.h`  
保留薄封装，只负责 frame 转发。
5. 修改 `app.c/.h`  
`app_init()` 只做一次 display init。  
`app_ui_tick()` 先跑诊断页，稳定10秒后才允许最小菜单壳。  
`app_measure_tick()` 仅门控，不启动真实测量。
6. 文档  
`README.md` 增加 Boot spine R1 启动流程、故障码、单写者说明。  
`docs/validation_checklist.md` 增加 R1 用例。  
新增 `docs/boot_flow_r1.md`：启动顺序、显示 ownership、fault code 表。

## 测试用例（必须逐项）
1. 正常上电  
PB12 先快闪后慢闪；OLED显示诊断页；5分钟稳定。
2. 故意断 OLED  
PB12 进入 fault 码 3 或 4；调试器可读 stage/fault；系统不中死。
3. 故意让 display init 失败  
通过 `app_display_service.c` 本地注入宏触发（默认0）；应报码3并可定位。
4. Error_Handler 验证  
人为触发错误后，仍有 fault 码与阶段信息，不再无信息死循环。
5. 单写者检查  
全工程正式路径仅一个 flush 调用点（display service 内部）。
6. 菜单门控  
诊断页未稳定10秒前不进入菜单；非 RUN 页不执行测量。
