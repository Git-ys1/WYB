## T-1.1.4M-R3 最终执行计划（仅 OLED 底层：上电时序 + reference init + 16-byte 分包 flush）

### 摘要
本轮只做 OLED 底层 R3 修复，不触碰业务架构。  
基于当前代码现状（已存在 smoke 模式、profile、page flush），本轮改为：

1. 冷启动前置延时 `250ms` 后再 probe。  
2. 默认只测 `SSD1315_PAGE`（不自动轮询 1306/1106）。  
3. init 序列替换为 reference 128x64 charge-pump 路径（含 `D9/DB/2E`）。  
4. flush 从“单页 129B”改为“每页 8 个 16B chunk”。  
5. 记录并导出失败落点（page/chunk/HAL status）。  
6. smoke 流程只跑命令+图案，不跑文本计数。  

---

### 1. 变更范围（严格）
仅改以下文件：

1. `BSP/bsp_oled_smoke.c`
2. `BSP/bsp_oled_smoke.h`
3. `Core/Src/main.c`（仅 smoke 分流与 smoke 流程调用）
4. `docs/oled_driver_report.md`
5. `docs/validation_checklist.md`

不改：`.ioc`、业务测量/菜单/按键/ADC/TIM/MUX/RGB主逻辑、Soft-I2C、恢复状态机。

---

### 2. 对外接口与类型变更（新增，便于定位失败）
在 `bsp_oled_smoke.h` 新增诊断类型与接口（不删旧接口，保持兼容）：

```c
typedef enum {
  OLED_SMOKE_FAIL_NONE = 0,
  OLED_SMOKE_FAIL_PROBE,
  OLED_SMOKE_FAIL_INIT,
  OLED_SMOKE_FAIL_FLUSH_CMD,
  OLED_SMOKE_FAIL_FLUSH_DATA
} oled_smoke_fail_stage_t;

typedef struct {
  oled_smoke_fail_stage_t stage;
  uint8_t page;      // 0..7, 失败时有效
  uint8_t chunk;     // 0..7, 失败时有效（16B分包）
  HAL_StatusTypeDef hal_status; // HAL_OK/HAL_ERROR/HAL_BUSY/HAL_TIMEOUT
} oled_smoke_diag_t;

void oled_smoke_diag_reset(void);
void oled_smoke_diag_get(oled_smoke_diag_t *out);
```

现有接口保留：
- `oled_smoke_init(...)`
- `oled_smoke_test_pattern(...)`
- `oled_smoke_get_first_packets(...)` 等

---

### 3. 核心实现决策（冻结）
#### 3.1 冷启动保护
在 OLED smoke 路径内，`MX_I2C2_Init()` 之后、首次 probe 之前执行：
- `HAL_Delay(250);`

#### 3.2 profile 固定
`main.c` 中 smoke 模式默认固定：
- `OLED_SMOKE_FORCE_PROFILE = OLED_PROFILE_SSD1315_PAGE`（值 `0`）
- 本轮不自动遍历 profile

#### 3.3 地址探测固定
地址顺序只允许：
1. `0x3C`
2. `0x3D`

参数固定：
- trials = `5`
- timeout = `25ms`（>=20ms，留裕量）

#### 3.4 reference init 序列（SSD1315/1306 family）
`bsp_oled_smoke.c` 采用以下顺序（page mode）：

`AE`
`D5 80`
`A8 3F`
`D3 00`
`40`
`8D 14`
`20 02`
`A1`
`C8`
`DA 12`
`81 CF`
`D9 F1`
`DB 40`
`A4`
`A6`
`2E`
`AF`

补充：
- 允许保留可切换宏做 A/B（`81 CF` vs `81 8F`），但默认 `CF`。

#### 3.5 flush 改 16-byte 分包
每页流程固定：
1. `B0 + page`
2. `00`
3. `10`
4. 数据分 8 次发送，每次 `0x40 + 16 字节`

即每页：
- `chunk = 0..7`
- 每次调用 `HAL_I2C_Master_Transmit(...)` 长度 `17`

#### 3.6 timeout 与状态记录
固定超时：
- probe: `25ms`
- cmd write: `25ms`
- data chunk write: `25ms`

每次 HAL 失败时记录：
- `stage`（probe/init/flush_cmd/flush_data）
- `page`
- `chunk`
- `HAL_StatusTypeDef`

#### 3.7 smoke 流程（仅图案）
`main.c` smoke 路径固定为：

1. `A5`（500ms）
2. `A4`（200ms）
3. 全黑（500ms）
4. 全白（500ms）
5. `AA/55` 条纹（1000ms）
6. 棋盘格（1000ms）

本轮不进入文本/CNT显示。

#### 3.8 PB12 错误码
保持并明确：
- `1 blink = probe fail`
- `2 blink = init fail`
- `3 blink = flush fail`

`3 blink` 的具体失败页/分包由 `oled_smoke_diag_get()` 和 report 记录。

---

### 4. main.c 调整规则（仅分流）
保留三路互斥，不混跑：
1. `APP_SMOKE_OLED_TEST=1`：仅 OLED smoke
2. `APP_SMOKE_OLED_TEST=0 && APP_SMOKE_LED_TEST=1`：LED smoke
3. 二者均 0：原业务入口

OLED smoke 路径只调用：
- `MX_GPIO_Init()`
- `MX_I2C2_Init()`
- `SmokeLed_Init()/SmokeLed_BlinkError()`
- `oled_smoke_*` 接口

不调用 `bsp_init()/app_init()/app_*tick`。

---

### 5. 文档更新要求
#### 5.1 `docs/oled_driver_report.md`
新增 R3 小节，固定包含：

1. R3 完整 init 序列（逐字节）
2. timeout 数值（probe/cmd/chunk）
3. page/chunk flush 写法（每页8个16B）
4. 两种上电方式对比表：
   - 冷上电（不按RST）
   - 按住RST上电再释放
5. 失败落点：
   - probe / init / flush
   - flush 时 page x / chunk y / HAL status

#### 5.2 `docs/validation_checklist.md`
新增 `T-1.1.4M-R3` 条目：
- 冷上电 probe 是否改善
- A5/A4 是否可见
- 图案链路是否规整
- 分包后花屏是否减少
- 失败落点是否可定位

---

### 6. 测试用例与场景（必须逐项）
1. `T114M-R3-01 冷启动探测`
- 断电>=2s后上电（不按RST）
- 观察是否仍 1 blink

2. `T114M-R3-02 RST辅助上电`
- 断电>=2s，按住RST上电后释放
- 比较与冷启动差异

3. `T114M-R3-03 命令链路`
- 观察 `A5 -> A4` 是否生效

4. `T114M-R3-04 图案链路`
- 黑/白/条纹/棋盘依次出现，且不乱序

5. `T114M-R3-05 flush失败定位`
- 若 3 blink，读取诊断并记录 `page/chunk/HAL status`

6. `T114M-R3-06 判定结论`
- 若仍完全一致失败：停止主工程修复，转入更换/交叉验证 OLED 模块流程

---

### 7. 显式假设与默认
1. OLED 模块仍为 4针 I2C、地址仅 `0x3C/0x3D`。  
2. I2C2 由 `MX_I2C2_Init()` 保持 100k。  
3. 本轮允许 smoke 使用 `HAL_Delay`。  
4. 默认 profile 固定 `SSD1315_PAGE`。  
5. 本轮目标是“定位底层链路问题”，不是恢复完整 UI/业务。
