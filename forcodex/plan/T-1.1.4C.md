# T-1.1.4C 一次到位修复计划（默认全功能启动 + OLED正常显示 + 防再次锁死）

## 摘要
目标是把当前固件从“保命模式”切回你要的“烧录即正常运行（含 OLED）”，同时保留已经证明有价值的抗锁死修复（不再全局关中断、增栈、去浮点 `printf`、保留 SWD）。  
本次不做“仅稳定性兜底”，直接交付可运行全功能默认配置。

## 详细实施步骤（决策完备）

## A. 恢复默认全功能启动（核心）
在 `App/app.c` 顶部宏区固定为：
- `APP_BOOT_SAFE_MODE = 0`
- 保留分阶段宏机制，但默认全部 `1`（OLED/I2C扫描/ADC/RES运行都开启）

并同步清理因 safe mode 引入的“未使用函数修饰”宏：
- 删除或最小化 `APP_MAYBE_UNUSED` 相关分支噪声，保证编译告警回到业务级别。

完成标准：
- 上电后会执行 OLED 初始化、I2C2 探测、ADC1 初始化、UI 页面刷新。

## B. 保留抗锁死修复（不回退）
保持以下现状不动：
1. `Error_Handler()` 不关总中断，仅陷入可调试循环。  
2. `HardFault_Handler` 记录 fault 标志与 SP。  
3. 链接脚本栈维持 `0x1000`。  
4. UI 显示仍使用定点字符串，不恢复 `%f` 打印。

完成标准：
- 全功能开启后，仍具备可连接/可定位能力，不回到“上电即黑死”。

## C. OLED 花屏专项修复（代码侧）
在全功能路径下固定以下行为：
1. `oled_init()` 成功后立即执行 `oled_clear + full flush`（当前已有，需保留）。  
2. 开机探测仅扫 `0x3C/0x3D`（保留当前优化，不再全扫 0~127）。  
3. UI 首屏刷新顺序固定：  
- 先写 L0/L1 基础系统行  
- 再写状态与日志行  
- 最后 `oled_flush_dirty`  
4. 若 `oled_flush_dirty` 连续失败 N 次（建议 N=3），触发一次 `oled_invalidate_all()` 强制整屏刷新恢复，避免局部刷新异常累积。

完成标准：
- 上电后屏幕在 1s 内出现可读文本，无“静止马赛克”。

## D. ADC/OLED联动恢复（功能完整）
恢复后保留当前逻辑：
1. `run_boot_selftest()` 中执行 ADC1 init + 一次 filtered read。  
2. `DEBUG` 页显示 `ADC raw / Vred / ADC stat`。  
3. `RES` 页继续使用定点字符串显示 `Vred` 与 `Rx`。  
4. 错误仅标记模块 FAIL，不允许阻塞主循环。

完成标准：
- 即使 ADC 读失败，OLED/按键/UI 仍继续运行，错误可见可恢复。

## E. Keil 下载错误联动排查（不改业务代码）
你强调优先代码，这里只做“最小必要核对”，不把问题甩给工具：
1. 确认本次输出 `Debug/WYB.hex` 来自上述全功能配置（非 safe mode）。  
2. Keil 若仍报 `Cannot Write to RAM for Flash Algorithms`，执行唯一标准化流程：
- 设备型号固定 `STM32G474VETx`
- Flash Algorithm 选 STM32G4 对应内部 Flash
- RAM for Algorithm 使用 `0x20000000` 区域
- SWD 速率降到 `100k~1MHz`
- `Connect under Reset`，**不要全程一直按住 RST**（仅用于连接阶段）
3. 若仍失败，记录 Keil `Utilities -> Settings` 页面截图（算法列表+RAM设置），作为后续唯一入口继续查。

完成标准：
- 至少可完成一次成功下载并运行新固件，排除“下载器配置阻塞”。

1. `T-REC-01`：不按住 RST，STLink 可 Attach。  
2. `T-REC-02`：连续 3 次下载+运行，无“运行后失联”。  
3. `T-OLED-01`：上电 1s 内出现 `BOOT/DEBUG` 文本。  
4. `T-OLED-02`：连续运行 5 分钟，无马赛克/静止花屏。  
5. `T-ADC-01`：DEBUG 页 `ADC raw/Vred/stat` 持续更新。  
6. `T-RES-01`：进入 RES 页面可显示 `ADC raw / Vred / Rx`。  
7. `T-ERR-01`：断开 ADC 输入后仅显示错误，不死机。  
8. `T-ERR-02`：I2C 瞬态异常后 OLED 可恢复刷新。

## 显式假设与默认
1. 默认以“代码修复优先”为主，不把根因归咎于 Keil。  
2. 默认目标是“全功能默认启动”，不是安全模式默认启动。  
3. 默认保留已有效的防锁死修复（Error/HardFault/栈/定点显示）。  
4. 若 Keil 仍下载失败，视为下载链路独立问题，按本计划 E 节最小闭环排查，不影响固件逻辑修复结论。
