# T-1.1.5F-R1 实施方案（统一显示架构，移除 Smoke 主流程依赖）

## 摘要
本轮目标是把“已验证的 `oled_smoke_*` 底层能力”从临时 smoke 模式升级为正式显示后端，并让主流程默认可显示、可导航、可回退。  
不做真实测量运行，仅恢复菜单壳浏览与 DEBUG/ADC 对照页。

基于当前仓库现状（已核查）：
1. `main` 当前默认仍是 smoke 路径（`APP_SMOKE_OLED_TEST=1`）。
2. `app.c` 目前仍包含旧的 OLED recover/soft-bus/dirty 分支与多处 flush 调用。
3. `App/app_ui_presenter.h` 当前不存在，`app_ui_presenter.c` 存在但不是薄封装。
4. `bsp_oled_smoke.*` 已稳定，且本轮禁止改其底层行为（init/remap/I2C/chunk）。

## 三、架构重构目标（决策完成）
### 目标架构
- `bsp_oled_smoke_*`：仅底层硬件后端（已冻结，不改）
- `app_display_service`：唯一“正式显示服务层”（初始化策略、页面渲染、flush、fallback）
- `app_ui_presenter`：仅薄封装（frame -> display_service），不再管理 init 策略
- `app.c`：菜单状态与页面文本组织，不直接触碰 OLED 底层 API
- `main.c`：始终走统一主流程（除紧急 LED smoke）

### 单写者规则（硬性）
1. 全项目正式路径只允许一个 flush 调用点：`app_display_service.c` 内部。
2. `app.c` 不允许调用 `oled_smoke_*` / `drv_oled_*`。
3. `main.c` 不允许再刷 OLED 页面（只做系统入口与 emergency LED 分流）。

## 四、文件级实施细则

## 4.1 新增 `App/app_display_service.h`
定义正式显示服务接口（任务书指定）：

- `app_err_t app_display_init(void);`
- `bool app_display_ready(void);`
- `app_err_t app_display_last_err(void);`
- `app_err_t app_display_show_boot(void);`
- `app_err_t app_display_show_adc_debug(uint16_t raw, bool raw_valid, uint32_t mv, bool mv_valid, uint32_t vdda_mv, bool vdda_valid, app_err_t stat);`
- `app_err_t app_display_show_menu_frame(const app_ui_frame_t *frame);`
- `app_err_t app_display_show_fallback(const char *err_tag);`

并在头文件中定义共用 frame 类型（供 presenter/app 复用）：
- `typedef struct { char line[8][22]; } app_ui_frame_t;`

> 说明：`app_ui_frame_t` 放在 service 头里，避免 presenter/app 各自重复定义。

## 4.2 新增 `App/app_display_service.c`
实现策略固定：

1. 初始化
- 内部固定调用 `oled_smoke_init(OLED_PROFILE_SSD1315_PAGE, OLED_ADDR_7BIT)`。
- 保留 `HAL_Delay(250)` 作为电源时序缓冲。
- 保存 `ready/last_err` 状态。

2. 唯一 flush 实现
- 私有函数 `display_flush_lines(const char lines[8][22])`：
  - `oled_smoke_fb_clear(0x00)`
  - `oled_smoke_draw_text_line(...)`
  - `oled_smoke_flush_full()`
- 全部显示 API 最终都走它。

3. fallback 策略
- 初始化失败或 flush 失败时，调用 `app_display_show_fallback("EX2"/"EX3")`。
- fallback 固定页（ASCII）：
  - `OLED FALLBACK`
  - `ERR: EXx`
  - `USE SMOKE BASE`
  - `CHECK EXP SWITCH`
- 失败不死锁：每次调用允许重试，不进入永久黑屏状态。

## 4.3 新增 `App/app_ui_presenter.h`
定义薄封装 API（保持 app 调用习惯）：
- `app_err_t app_ui_presenter_init(void);`
- `bool app_ui_presenter_ready(void);`
- `app_err_t app_ui_presenter_last_err(void);`
- `app_err_t app_ui_presenter_flush(const app_ui_frame_t *frame);`

## 4.4 重写 `App/app_ui_presenter.c` 为薄封装
只做转发，不再自管初始化/fallback策略：
- `app_ui_presenter_init -> app_display_init`
- `app_ui_presenter_ready -> app_display_ready`
- `app_ui_presenter_last_err -> app_display_last_err`
- `app_ui_presenter_flush -> app_display_show_menu_frame`

禁止保留：
- presenter 内部 `oled_smoke_*` 调用
- presenter 内部 fail_streak/init策略

## 4.5 改 `Core/Src/main.c`（去 smoke 主流程依赖）
1. 删除/停用 `APP_SMOKE_OLED_TEST` 和 `APP_MENU_REINTEGRATION_EXPERIMENT` 对正式显示的控制。
2. 保留一个紧急 LED 宏即可（例如 `APP_EMERGENCY_LED_SMOKE_TEST 0`）：
- `0`：永远走正式主流程：
  - `HAL_Init -> Clock -> MX_* -> bsp_init -> app_init -> superloop`
- `1`：仅用于紧急 LED 救援。
3. 正式路径中不允许任何 OLED smoke 页面渲染逻辑。

## 4.6 改 `App/app.c`（简化为菜单壳 + 单写者输出）
### 必须完成
1. 去掉旧复杂显示链路依赖：
- 移除直接 `drv_oled_ssd1306` 调用路径
- 移除旧 recover/soft bus/dirty flush 调度路径调用
2. 仅通过 presenter 输出：
- `app_ui_tick()` 构建 `app_ui_frame_t`
- 每次 tick 最多一次 `app_ui_presenter_flush()`
3. `app_init()`：
- 先 `app_ui_presenter_init()`
- 成功显示极简首页（可通过首次 `ui_dirty=true` 触发）
- 失败走 fallback（调用 `app_display_show_fallback("EX2")` 或由 presenter 返回后 app 调用）
- 系统继续运行，不死循环

### 菜单层级恢复（仅浏览）
- `L1_MODULE`
- `L2_DEBUG_PAGE`
- `L2_MEAS_FUNC`
- `L3_RES_RANGE`
- `L4_RES_READY`
- 预留 `MENU_L4_RES_RUN` 但本轮不进入

### 页面文本固定
1. 首页：
- `MAIN MENU`
- `> DEBUG`
- `  MEASURE`（光标随选择变化）

2. DEBUG/ADC 页（稳定对照）：
- `RAW:`
- `MV :`
- `VDDA:`
- `STAT:`

3. MEASURE 功能页（浏览）：
- `RES`
- `VDC`
- `FREQ`
- `CONT`
- `DIODE`

4. RES RANGE 页：
- `AUTO / 200 / 2K / 20K / 200K`

5. RES READY 页：
- `RES READY`
- `RANGE: xxx`
- `PRESS OK TO RUN`
- `RUN DISABLED`

### 测量门控
`app_measure_tick()` 固定：
- 非 `MENU_L4_RES_RUN` 或 `meas_run_enabled=false` -> 立即 return
- 本轮 `MENU_L4_RES_RUN` 不可达，故不会执行真实测量
